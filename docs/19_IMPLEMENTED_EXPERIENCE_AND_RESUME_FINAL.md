## 一、本轮实现后，项目发生了什么变化

### 1. 项目定位没有改变，但业务故事更完整

项目仍然是“注塑工艺参数与质量智能决策平台”，不是设备控制系统，也不是算法研发平台。本轮没有改变核心定位，而是把两个已经确认的用户痛点做成真实页面闭环：

```text
多源生产数据
→ 从 429 项跨数据源字段中检索目标字段
→ 以纵向详情查看单条记录，按需选择字段比较记录
→ 导入训练/调参数据并选择模型
→ 明确选择 CSV 样本或手工参数作为比较方案，冻结来源与原始推荐
→ 在人工工作稿中修改 76 项参数
→ 查看字段级差异并试算当前方案
→ 参数或上下文变化时标记旧质量结果过期
→ 使用真实选择的机台、模具、材料和产品保存方案
```

此前项目更偏向“参数 Schema、CSV、状态机和请求治理”等底层工程能力；现在增加了用户可以直接感知的参数探索、方案对比、回退和结果有效性提示，业务价值与技术实现能够形成同一条故事。

### 2. 高维工业参数探索已经实现

原数据管理页面根据第一条记录生成全部表格列。机台参数样例每条有 260 个字段，即使只有 9 条记录，页面仍需要创建约 260 列，用户只能依赖横向滚动查找。

当前实现包括：

- 为五类数据建立统一字段目录，字段拥有稳定 ID、原始键、中文名称、别名、业务分组和可用状态；
- 兼容接口原始键和仓库中文样例，避免同一字段因两种名称被重复计算；
- 页面只展示用户选择的 4～6 个摘要字段，不再默认挂载全部列；
- 支持按中文名称、原始键或业务分组检索；
- 单条记录以“字段一行、值一列”的纵向方式展示，每页最多 50 项；
- 最多选择 3 条记录、30 个字段进行差异对比，并可只看变化项；
- 全量 Excel 导出仍保留，不因页面按需展示而丢失数据。

使用仓库 9 条机台参数样例进行页面验证时，字段目录正确识别 261 项定义、260 项实际字段和 16 个业务分组；搜索“射胶压力”可定位到唯一字段，记录对比能显示具体变化值。这里的数字是本地样例事实，不代表线上数据规模或性能提升。

### 3. 工艺方案实验室已经实现

原调参页面会把算法推荐直接覆盖到可编辑表单。用户修改后，页面无法清楚回答：原始推荐是什么、改了哪些字段、当前质量结果使用哪一版参数、生产上下文变化后结果是否仍有效。

当前实现包括：

- 在调用推荐前冻结带来源的“推荐前比较方案”，返回后冻结“算法原始推荐”；
- 用户始终编辑独立的人工工作稿，不会覆盖基线和原始推荐；
- 支持“基线→推荐”“推荐→人工稿”“基线→人工稿”三种字段级差异；
- 支持只看变化项，并对数值变化展示增减方向；
- 支持一键恢复调参基线或算法原始推荐；
- 当前人工稿可直接调用既有质量预测接口进行独立试算；
- 质量结果绑定提交时的参数指纹和生产上下文，之后修改参数、模型、任务或上下文会自动标记结果过期；
- 保存前要求当前方案已经重新试算，并使用实际选择的机台、模具、材料和产品替代原有固定值。

### 4. 同时修正的相关业务问题

- 历史方案页面改为真正使用筛选和分页后的数据，而不是始终渲染全量数组；
- 修正产品编码筛选变量大小写错误；
- 历史筛选候选值会过滤空值并统一为字符串，避免搜索时调用字符串方法报错。

这些修正保证新保存的上下文能够被历史页面检索，但它们属于业务闭环的必要工作，不单独包装成简历亮点。

### 必须保留的前后端边界

1. 字段目录、搜索、投影、diff、回退和结果过期判断是前端能力；数据是否完整、单位和范围是否权威仍由后端/业务方负责。
2. “推荐前比较方案”可从明确选择的 CSV 样本载入或手工确认；页面显示字段映射覆盖率，仍不冒充实时读取的注塑机生产值。推荐接口当前不接收该方案，它只作为差异比较参照。
3. 质量结果由算法服务返回；前端只保证结果绑定正确的参数和上下文，不能声称保证预测准确或推荐安全。
4. 当前快照是页面内状态，历史接口只保存参数和四类上下文字段，尚未持久化完整 diff、模型、任务和质量结果。
5. 前端取消 HTTP 请求不等于服务端训练已停止；真实异步 job、幂等唯一约束和取消结果仍需后端实现。

## 三、最终保留的四个亮点与取舍

### 1. 高维工业参数探索

它直接解决用户已经实际感受到的“字段太多、页面很难看”的问题，同时展示数据建模、信息架构和渲染控制。相比直接增加横向虚拟滚动，当前方案先减少用户需要同时理解的字段和页面实际创建的列，更贴近真实任务。

### 2. 工艺方案实验室

它把 76 项 Schema 从底层重构升级为用户可见的决策能力：算法建议不再覆盖，人工修改可比较和回退，质量结果有明确输入版本。它同时体现复杂交互、不可变状态和异步结果正确性，是最适合深入追问的业务亮点。

### 3. 资源受控的 CSV 导入管线

它是模型训练和参数推荐的数据入口，体现浏览器文件处理、资源预算、有限预览和异常反馈。当前仍不写“完整工业数据质量规则”，因为两个业务 Schema 没有权威 columns、单位和范围。

### 4. 可恢复的模型训练工作流

它体现长任务状态建模、草稿恢复、幂等和乱序状态处理。五步状态与前端任务协议已经实现并测试，但默认后端还是 legacy，因此简历继续使用“设计验证”，不写成完整任务中心已经上线。

### 被降为支撑能力的内容

请求 latest-only、统一错误模型、历史筛选修正和 Element UI 组件使用仍然真实，但它们现在服务四条业务主线，不再单独占用简历位置。

## 四、可直接放入简历的最终固定版本

### 【注塑工艺参数与质量智能决策平台】

**项目技术栈：**Vue 2、JavaScript（ES6+）、Vue Router、Vuex、Element UI、Axios、Papa Parse、ECharts、Vue CLI、Node.js Test Runner

**项目描述：**面向注塑工艺与质量人员，构建集多源生产数据探索、模型训练、工艺参数推荐、方案对比与质量试算于一体的智能决策系统，辅助完成从数据准备、参数分析到人工确认的工艺决策。

**主要工作：**

1. 针对 429 项跨数据源字段及单条约 260 列机台参数难搜索、难比较的问题，基于统一字段目录实现中英文别名检索、纵向详情与选列差异对比，避免用户在超宽表中反复横向查找。
2. 针对算法推荐易覆盖比较方案、质量结果易与当前输入错配的问题，保留推荐前方案、算法建议与可编辑工作稿，支持字段级差异和回退；将质量结果绑定提交时的参数与生产上下文，输入变化后标记旧结果失效。
3. 针对训练与调参 CSV 数据规模和格式不可控、全量渲染风险，基于 Papa Parse 分块解析、资源预算与有限预览实现可取消导入，在数据进入算法前拦截超限文件和结构错误。
4. 针对模型训练耗时长、刷新丢步骤和重复提交问题，将五步流程建模为可恢复状态机，并设计验证 jobId、幂等键、状态版本、退避轮询与取消语义，避免任务状态被旧响应回退。

四条分别约 85、89、86、82 个字符，均保持在约 60～100 个字符内。正文不再额外加入请求封装、路由懒加载、按需引入和一般修复。

## 六、四个亮点的通俗解释与面试准备

## 亮点一：高维工业参数探索

### 为什么会出现这个问题

系统的字段目录覆盖机器、模具、材料、产品和机台参数五类数据，共 429 项映射。机台参数样例单条约 260 个字段；这里的“长”不是记录行数，而是单条记录特别宽。

### 原方案有什么不足

原页面遍历首条记录的全部 key 创建表格列。行分页只能减少同时显示的记录数，不能减少 260 列，也不能帮助用户回答“字段属于什么组、两条记录哪里不同”。

### 前端具体如何实现

1. 将 fieldMaps 和实际记录合并成字段目录，为字段保存稳定 ID、原始键、中文名、别名、分组和可用状态；
2. 对原始键和已翻译中文键进行归一，避免同一字段重复；
3. 概览默认只投影少量摘要字段；
4. 搜索和分组先筛选字段集合，再把单条记录转成纵向行；
5. 详情每页只渲染 50 项；
6. 对比视图只处理用户选择的记录和字段，并按 `Object.is` 判断值是否变化。

### 使用了哪些浏览器或框架能力

主要使用 Vue computed 计算投影结果、Element UI 的 Tabs/Table/Pagination/Select 承载交互，并用 `Map`、`Set` 和纯函数建立目录与比较。当前没有使用虚拟列表或 Worker，因为本地样例在纵向分页和限定对比字段后没有证明仍需要它们。

### 最终给用户带来什么

用户可以从中文名、原始键或业务组直接找到字段；单条记录不再默认生成约 260 个列节点；比较时可以只看选中字段的变化值。

### 其他方案及取舍

- 横向虚拟表格：能减少列 DOM，但用户仍要在超宽空间里找字段；
- 只做列固定或横向滚动：实现简单，但没有解决搜索和比较；
- 后端返回窄表：适合大规模查询，但会改变接口结构，本轮先在前端基于现有数据完成验证；
- Worker：只能转移字段统计 CPU，不能改善信息组织，也不能降低全部数据的网络和内存成本。

### 前端与后端的边界

前端负责字段目录、别名、搜索、投影和比较；后端负责分页查询、字段版本、单位和数据真实性。页面显示“261 项目录、260 项实际字段”只来自当前样例，不能推广成所有生产数据都固定为这个规模。

### 面试官可能继续追问

- 为什么 260 列不直接使用横向虚拟化？
- 字段 ID 为什么不能直接用中文名称？
- 原始键和中文键同时出现时如何去重？
- 记录继续增长后怎样改成服务端分页？
- 如何测量首次渲染节点数和 Long Task？

## 亮点二：工艺方案实验室

### 为什么会出现这个问题

算法推荐只是候选方案。工艺人员可能继续修改参数；如果页面只保留一份可编辑对象，修改后就无法确认哪些值来自算法，质量结果也可能仍对应修改前参数。

### 原方案有什么不足

直接把推荐结果覆盖到表单，会让“事实”和“工作状态”混在一起。仅保存一个 revision 也不够，因为生产上下文、模型或任务改变时，即使参数数字没变，旧质量结果也可能不再适用。

### 前端具体如何实现

1. 从 CSV 样本或手工参数明确建立推荐前比较方案，记录来源和映射覆盖率，推荐请求前冻结该方案；
2. 快照深冻结，人工编辑只产生新的工作稿 revision；
3. 基于稳定参数 ID 计算 76 项差异，并提供三种比较方向；
4. 通过参数指纹和稳定排序的上下文指纹绑定一次质量结果；
5. 参数、机台、模具、材料、产品、模型、任务、算法或数据集变化后，旧结果进入 stale 状态，并区分参数变化与上下文变化；
6. 允许恢复基线/推荐，并调用既有 26 项质量预测接口重新试算当前工作稿；
7. 保存时要求上下文完整且当前结果未过期。

### 使用了哪些浏览器或框架能力

使用 `Object.freeze` 和纯函数构造不可变快照，使用 JSON 指纹比较参数及上下文内容，使用 Vue computed 实时生成 diff 和 stale 状态；重新试算通过 Axios 与 `AbortController` 调用现有预测接口。

### 最终给用户带来什么

用户能明确区分基线、算法建议和自己的修改，只看变化字段并随时回退；参数或上下文改变后，页面不会继续把旧质量结果显示成当前方案的有效结果。

### 其他方案及取舍

- 深拷贝后直接比较整个对象：能工作，但缺少稳定字段身份、业务分组和可解释 diff；
- 只比较 revision：实现简单，但恢复相同值后仍会误判，且无法识别上下文变化；
- 使用 Vuex 保存全部快照：适合跨组件共享，但刷新仍会丢失，真正跨设备追踪需要后端方案实体；
- 采用完整事件溯源：可审计性更强，但需要后端存储和版本协议，超出当前前端最小闭环。

### 前端与后端的边界

前端保证一次结果对应正确的输入快照；算法方负责预测准确性和推荐安全性。当前历史接口没有保存完整快照链和质量结果，因此只能说页面内可比较、可回退，不能声称已经实现生产级审计追溯。

### 面试官可能继续追问

- 为什么使用内容指纹而不是只用 revision？
- 快照为什么要不可变？
- 参数恢复后旧预测结果是否仍然有效？
- 异步预测返回前用户再次编辑参数怎么办？
- 如何把页面快照升级为后端持久化的方案版本？

## 亮点三：资源受控的 CSV 导入管线

### 问题与实现

CSV 文件可能包含异常表头、坏行或过多单元格。当前管线基于 Papa Parse 分块解析，组合限制文件字节、行数、列数、单元格数和单格长度，提供进度、取消、错误采样与有限预览；完整 rows 放在非响应式 repository，通过 importId 引用和释放。

### 用户结果

超限和基础结构错误在数据进入算法前被拦截，导入可以取消，表格只创建有限预览行。分块解析仍保留全量 rows，因此极大数据仍应转向后端上传，而不是宣称前端已经解决任意规模文件。

### 方案取舍与追问

- Worker 能减少 CPU 阻塞，不能减少全量数据内存；
- 一次性 FileReader 更简单，但资源峰值更难控制；
- 后端上传适合大数据，但需要 datasetId、存储和服务端规则；
- 面试可继续追问组合预算、错误采样上限、保守类型推断和取消时序。

## 亮点四：可恢复的模型训练工作流

### 问题与实现

训练包含任务信息、数据、特征、算法和结果多个阶段。页面将流程建模为事件驱动状态迁移，前序变化会使后序失效，草稿只保存可恢复元数据；异步模式设计了 jobId、幂等键、statusVersion、退避轮询、页面隐藏降频和取消语义。

### 用户结果

页面能够解释当前阶段和合法操作，刷新后按草稿和 job 信息恢复；旧状态响应不会让进度倒退，取消请求失败也不会伪装成任务已经停止。

### 方案取舍与追问

- loading 变量无法表达长任务生命周期；
- WebSocket/SSE 需要真实推送协议和断线恢复；
- localStorage 不能恢复 File；
- 面试可继续追问幂等键、状态版本、轮询退避以及前端取消与服务端取消的区别。

## 八、验证结果

### 自动化与构建

- `npm test`：48 项测试全部通过；覆盖字段目录、别名归一、纵向投影、记录对比、快照、diff、恢复、stale 判断及演示模式开关与样例 CSV；
- `npm run build`：生产构建成功；仍有 ECharts 默认导入、vendor 体积和入口体积三类既有警告；
- 未修改后端和算法实现，所有新增行为均通过当前接口或本地确定性样例完成验证。

### 页面级验证

项目现已内置可切换的纯前端演示适配器，无需额外 Mock 服务即可加载仓库样例并验证四条流程：

1. 页面显示 261 项目录字段、260 项实际字段和 16 个业务分组；
2. 初始概览只生成 4 个摘要数据列，不再生成 260 个业务列；
3. 搜索“射胶压力”只得到一个字段，并能在纵向详情显示原始键和值；
4. 默认选择两条记录进行比较，changed-only 表格正确显示变化字段及两侧值；
5. 调参页面可一键加载演示 CSV、模型和四类生产上下文，确定性模拟推荐与试算用于验证方案快照、回退和 stale 提示；
6. 训练页面可走通 CSV 导入、五步状态机、阶段进度、取消与刷新恢复；浏览器模拟 job 只验证前端协议，真实服务仍需后端联调。

纯前端模式默认开启；设置 `VUE_APP_DEMO_MODE=false` 后仍使用真实业务与算法接口。页面持续显示演示边界，不能把模拟结果解释为真实模型精度。
