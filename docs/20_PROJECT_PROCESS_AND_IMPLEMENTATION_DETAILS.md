# STEP 20：项目业务过程、实现细节与面试讲解

> 适用方向：Vue / React 前端开发，校招或初级岗位  
> 文档用途：解释简历中四个核心亮点所对应的业务过程、代码实现、技术取舍与前后端边界。  
> 真实性说明：高维参数探索、方案实验室、CSV 导入和训练状态机均已完成前端实现；推荐、预测与异步训练在纯前端模式下使用确定性模拟结果，不代表真实算法服务已经上线。

---

## 一、项目整体业务

项目面向注塑工艺和质量人员。注塑生产中，一件产品的质量会受到机台、模具、材料以及大量工艺参数共同影响。

四个核心亮点并不是四个孤立页面，而是组成了一条完整业务链：

```text
浏览多源生产数据
→ 定位目标参数和异常记录
→ 导入训练或调参 CSV
→ 选择模型、算法和生产上下文
→ 获得参数推荐
→ 人工调整、比较和回退
→ 重新进行质量试算
→ 保存方案或提交模型训练
```

系统主要解决四类问题：

1. 生产数据字段很多，传统宽表难以查找和比较；
2. 算法推荐后还需要人工调整，但原始推荐容易被覆盖；
3. 训练数据来自 CSV，文件格式和数据规模不可控；
4. 模型训练时间较长，刷新、重复提交和任务状态容易混乱。

前端主要分为四层：

- 页面层：数据管理、参数调优、模型训练等 Vue 页面；
- 领域层：字段目录、参数 Schema、CSV 导入、训练状态机等纯 JavaScript 模块；
- 请求层：Axios 客户端、错误标准化、请求取消和竞态控制；
- 演示层：Axios Demo Adapter，在没有后端时返回确定性业务数据。

简历定稿参见 [19_IMPLEMENTED_EXPERIENCE_AND_RESUME_FINAL.md](./19_IMPLEMENTED_EXPERIENCE_AND_RESUME_FINAL.md)。

## 二、亮点一：高维工业参数探索

### 1. 为什么会出现问题

机台参数样例单条记录约有 260 个字段。原页面根据第一条记录的所有 key 动态生成表格列，因此即使只有几条记录，也会产生约 260 个业务列。

分页只能减少“行”，无法减少“列”，用户仍然需要不断横向滚动，而且很难回答：

- “射胶压力”对应哪个原始字段；
- 这个参数属于哪个业务阶段；
- 两条机台记录到底有哪些参数不同；
- 某个字段是没有采集，还是值为空。

### 2. 字段目录如何建立

选择数据类型后，页面获取记录并调用 `buildFieldCatalog` 建立统一字段目录，核心实现位于 [highDimensionalExplorer.js](../src/domain/data/highDimensionalExplorer.js)。

每个字段会被转换为类似结构：

```js
{
  id: "机台参数::injection_pressure_3",
  rawKey: "injection_pressure_3",
  label: "注射－压力三段",
  group: "注射",
  aliases: ["injection_pressure_3", "注射－压力三段"],
  sourceKeys: ["injection_pressure_3", "注射－压力三段"],
  available: true
}
```

字段属性的作用如下：

- `id`：使用“数据类别 + 原始字段”生成稳定身份；
- `rawKey`：对应接口中的原始字段；
- `label`：用于中文展示；
- `aliases`：同时支持中文名和原始键搜索；
- `group`：根据中文名称中的业务前缀推断；
- `available`：表示本批数据是否真的出现了这个字段。

如果数据中直接使用中文字段名，而映射表中保存的是英文原始键，目录会将它们归一成同一个字段，避免出现两个重复列。

### 3. 页面如何减少信息量

数据管理页面不再默认生成全部列，而是分成三个视图，页面实现在 [dataManage.vue](../src/views/dataManage.vue)。

#### 3.1 记录概览

默认从不同业务分组中挑选 4 个摘要字段，用户最多可以选择 6 个。

因此页面初始只创建：

```text
记录列 + 4～6 个摘要字段 + 操作列
```

而不是直接创建约 260 个参数列。

#### 3.2 纵向详情

点击某条记录后，将它转换成纵向结构：

| 业务分组 | 字段名称 | 原始字段 | 当前值 |
| --- | --- | --- | --- |
| 注射 | 注射－压力三段 | injection_pressure_3 | 118 |
| 保压 | 保压－时间三段 | holding_time_3 | 9.5 |

纵向详情沿用搜索和分组条件，每页最多展示 50 个字段。用户搜索“射胶压力”后，只需要查看与目标相关的几行。

#### 3.3 选列对比

用户最多可以选择：

- 3 条记录；
- 30 个字段；
- 是否只看变化项。

比较时，前端根据稳定字段 ID 读取每条记录的值，再通过 `Object.is` 判断值是否一致。这里同时区分：

- 字段未采集；
- 字段存在但值为空；
- 字段值真正发生变化。

### 4. 为什么不直接使用虚拟列表

虚拟列表可以减少当前创建的 DOM 数量，但用户仍然需要在 260 列的横向空间中寻找目标字段。当前方案先解决信息组织问题：

```text
全量字段
→ 搜索和分组
→ 用户选择字段
→ 页面只投影需要的数据
```

如果未来记录数量继续增加，可以补充服务端分页；如果纵向详情经过实测仍出现 Long Task，再考虑虚拟列表或 Worker。

### 5. 用户得到什么

用户可以直接搜索参数、查看单条记录、比较多条记录，而不需要在超宽表中反复横向滚动。完整数据仍然可以导出 Excel，不会因为页面只展示摘要而丢失。

### 6. 前后端边界

前端负责字段目录、别名搜索、信息分组、按需投影和记录比较；后端负责真实数据、字段版本、单位、服务端查询和分页。页面中的字段数量来自仓库样例，不能推广为所有生产数据都固定为这个规模。

## 三、亮点二：工艺方案实验室

### 1. 原方案的问题

算法推荐只是一个候选方案，工艺人员通常还会继续手动调整。如果推荐结果直接覆盖当前表单，用户修改后就无法知道：

- 推荐前的参数是什么；
- 算法原始建议是什么；
- 自己修改了哪些参数；
- 当前质量结果对应修改前还是修改后的参数；
- 更换机台或模具后，旧结果是否仍然有效。

### 2. 76 项参数 Schema

项目为可调工艺参数建立了统一 Schema。每个参数拥有稳定 ID，以及不同接口需要的名称。

同一个参数可能存在四种表示：

```text
页面字段 ID
历史方案字段名
推荐接口字段名
质量预测接口字段名
```

前端通过 Adapter 在这些格式之间转换：

```text
接口 DTO
→ 转换为统一参数表单
→ 用户编辑
→ 根据目标接口转换回对应 DTO
```

这样推荐、编辑、保存和预测都围绕同一套字段身份工作，而不是在页面里散落大量字符串判断。参数 Schema 和转换逻辑分别位于 [parameterSchema.js](../src/domain/parameter/parameterSchema.js) 与 [parameterTransform.js](../src/domain/parameter/parameterTransform.js)。

### 3. 四种状态分别是什么

方案实验室维护四类状态：

- 推荐前比较方案：由用户明确选择的 CSV 样本或手工参数构成，并记录来源和字段映射覆盖率；
- 推荐快照：算法返回并转换后的原始推荐；
- 人工工作稿：用户当前正在编辑的参数；
- 预测快照：最近一次质量结果实际使用的参数和上下文。

快照由 `createParameterSnapshot` 创建，并通过递归 `Object.freeze` 冻结，实现在 [parameterScenario.js](../src/domain/parameter/parameterScenario.js)。

快照不能被直接修改。否则基线可能随着人工工作稿一起变化，后续差异比较和方案回退会失去意义。

### 4. 参数推荐流程

用户点击“参数推荐”后，前端执行以下过程：

1. 检查 CSV 是否已经导入；
2. 检查模型和算法是否已经选择；
3. 收集机台、模具、材料、产品、模型、任务和数据集上下文；
4. 从 CSV 样本或手工参数建立比较方案，在发送请求前连同来源一起冻结；
5. 使用 `AbortController` 取消上一次未完成的推荐；
6. 将完整数据集提交给推荐接口；
7. 解析推荐参数和质量结果；
8. 将接口字段转换为统一参数表单；
9. 创建推荐快照和预测快照；
10. 默认展示“基线 → 推荐”的变化字段。

页面流程位于 [ParameterTuning.vue](../src/views/ParameterTuning.vue)。

### 5. 差异是如何计算的

前端支持三种比较方向：

```text
比较方案 → 推荐
推荐 → 人工稿
比较方案 → 人工稿
```

`compareParameterStates` 会按照 76 项 Schema 的顺序逐个比较，而不是遍历任意对象的 key。

每个差异项包含：

```js
{
  fieldId,
  label,
  groupLabel,
  before,
  after,
  changed,
  numericChange
}
```

如果前后都是有效数字，还会计算增减量，例如 `+8` 或 `-2.5`。页面可以选择显示全部参数或只显示变化项。

### 6. 为什么质量结果会“过期”

一次质量结果必须绑定两个输入：

```text
参数内容 + 生产上下文
```

参数指纹按照固定的 76 项字段顺序序列化；上下文指纹则先对对象 key 稳定排序，再进行序列化。这里的“指纹”不是加密哈希，而是稳定的内容表示。

当下列任一内容变化时，旧结果都会被标记为 stale：

- 任一工艺参数；
- 机台、模具、材料或产品；
- 模型或任务；
- 算法；
- 缩减比例；
- 数据集身份及行列信息。

因此，用户修改参数或更换生产上下文后，页面不会继续把旧质量结果展示成当前方案的有效结果。

### 7. 重新试算如何避免结果串线

用户点击“试算当前方案”时：

1. 先校验当前参数；
2. 冻结本次提交的参数和上下文；
3. 转换出质量预测接口需要的 26 项输入；
4. 创建新的 `AbortController`；
5. 请求完成后验证返回结构；
6. 使用提交时的快照保存结果，而不是使用返回时可能已经变化的表单。

因此，即使用户在请求过程中继续编辑参数，也能识别返回结果已经过期。

### 8. 保存方案前的限制

保存前必须满足：

- 参数校验通过；
- 最近一次质量结果没有过期；
- 机台、模具、材料和产品均已选择。

这避免用户把“没有重新计算的旧结果”当成当前方案结果保存。

### 9. 前后端边界

前端保证一次质量结果绑定正确的输入快照；算法服务负责预测准确性和推荐安全性。当前推荐接口只接收模型、算法、比例和数据集，推荐前方案只是比较参照，不是算法输入；历史接口也没有保存完整快照链、差异、模型和质量结果，因此只能描述为“页面内可比较、可回退”，不能描述为生产级审计系统。

## 四、亮点三：资源受控的 CSV 导入

核心实现位于 [datasetImporter.js](../src/domain/dataset/datasetImporter.js)。

### 1. 导入前检查

文件进入解析器前先检查：

- 扩展名必须为 `.csv`；
- 文件不能为空；
- 默认不能超过 20 MB；
- MIME 类型异常时给出警告，但继续按照内容校验。

### 2. 分块解析

项目使用 Papa Parse 的 `chunk` 回调，每次默认解析约 1 MB，而不是一次性同步处理完整文件。

每处理一个分块，页面都会收到：

```js
{
  processedUnits,
  totalUnits,
  percent,
  rowCount
}
```

因此页面可以展示进度，也可以在解析过程中取消。

### 3. 表头校验

第一块数据到达后生成表头计划，检查：

- 空表头；
- 重复表头；
- 超过 256 列；
- Schema 未定义字段；
- 缺少必需字段；
- `__proto__`、`prototype`、`constructor` 等危险字段。

最后一项用于避免将不可信字段写入普通对象时产生原型污染风险。

### 4. 类型转换

Papa Parse 的自动类型推断被关闭，由项目自己进行保守转换：

- `true/false` 转为布尔值；
- 安全数字转为 `Number`；
- 带前导零的内容保留为字符串，避免产品编号 `001` 变成数字 `1`；
- `NaN` 和 `Infinity` 被拒绝；
- 超过 JavaScript 安全数值范围的内容不会被强制转换；
- 如果 Schema 定义了类型，还会检查整数、枚举、日期、最小值和最大值。

### 5. 组合资源预算

默认同时限制：

| 资源 | 默认上限 |
| --- | ---: |
| 文件大小 | 20 MB |
| 行数 | 100000 |
| 列数 | 256 |
| 单元格总数 | 2000000 |
| 单个单元格长度 | 10000 个字符 |
| 页面预览行数 | 200 |
| 错误样本数量 | 200 |
| 解析分块大小 | 1 MB |

只限制文件大小并不够，因为一个体积不大的 CSV 也可能包含极多短字段。行数、列数和单元格数共同限制，才能控制浏览器内存和处理时间。

### 6. 为什么完整数据不放进 Vue 响应式状态

解析成功后采用以下结构：

```text
完整 rows → 模块级 Map 仓库
previewRows → Vue 页面
importId → Vuex 或页面状态
```

完整数据保存在 [datasetRepository.js](../src/domain/dataset/datasetRepository.js) 的普通 `Map` 中，页面只保存 `importId` 和有限预览。

这样可以避免 Vue 2 为全部数据建立响应式依赖，也避免表格渲染全部行。但完整数据仍然占用浏览器内存，所以不能声称前端已经解决任意规模 CSV。更大的数据应该改成分片上传，由后端返回 `datasetId`。

### 7. 错误反馈和取消

解析器会记录错误总数、错误类型、行号、列名和原始值，但页面只保留有限错误样本，防止坏数据产生数量过大的错误列表。

用户取消或重新选择文件时，前端会终止当前解析任务、释放旧 `importId` 对应的数据，并阻止已经过期的解析结果重新写入页面。

### 8. 当前真实边界

目前训练和调参的业务 Schema 还没有权威 columns，因此当前已经实现的是：

- 文件结构校验；
- 资源预算；
- 安全类型推断；
- 解析错误定位；
- 进度和取消；
- 有限预览。

当前还不能声称已经完成注塑领域的单位、范围、必需列和跨字段工艺规则校验。

## 五、亮点四：可恢复的模型训练工作流

### 1. 五步页面和内部状态

用户看到的是五步：

```text
任务信息 → 数据选择 → 特征工程 → 算法选择 → 运算结果
```

内部状态更细：

```text
taskInfo
dataset
features
algorithm
submitting
tracking
result
```

增加 `submitting` 和 `tracking` 是因为“正在创建任务”和“任务已经创建、正在训练”具有完全不同的恢复与错误处理方式。

### 2. 为什么使用状态机

如果只维护：

```js
step = 4
loading = true
```

无法表达：

- 是否已经创建 job；
- 是否可以取消；
- 创建结果是否未知；
- 是否允许重新提交；
- 旧轮询结果能否更新当前任务；
- 失败后应该回到哪一步。

项目将所有操作转换为事件，例如：

```text
SAVE_TASK_INFO
SELECT_DATASET
CONFIRM_FEATURES
SUBMIT_JOB
JOB_CREATED
JOB_UPDATED
CANCEL_REQUESTED
POLL_FAILED
RESET
```

事件只能在允许的状态触发，核心迁移函数位于 [trainingWorkflow.js](../src/domain/training/trainingWorkflow.js)。

例如，在数据步骤没有有效 `importId` 就不能进入特征步骤；没有算法和数据集就不能提交训练。

### 3. 幂等键解决什么问题

用户点击提交后，如果请求超时，前端无法确定：

```text
服务端没有收到请求
还是
服务端已经创建任务，但响应丢失
```

如果直接再提交一次，可能创建两个训练任务。因此每次提交会生成一个幂等键，并通过 `Idempotency-Key` 请求头发送。

创建结果不确定时，重新确认会复用原来的幂等键，而不是生成新键，还可以通过以下接口找回任务：

```text
/training-jobs/by-idempotency-key/{key}
```

真正的唯一约束必须由后端实现；纯前端演示只验证协议和页面行为。

### 4. 状态版本如何防止进度倒退

网络请求可能乱序返回。例如：

```text
新请求返回 running / 72%
旧请求稍后返回 running / 38%
```

每个 job 都带有 `statusVersion`。处理新状态时：

- 版本小于当前版本：直接忽略；
- 版本相同但内容不同：判定为协议冲突；
- `jobId` 不同：拒绝更新；
- 状态迁移不合法：拒绝更新；
- 只有更新版本和合法迁移才能进入页面。

因此旧响应不会把进度从 72% 改回 38%。

### 5. 轮询策略

轮询器位于 [trainingJobPoller.js](../src/domain/training/trainingJobPoller.js)，包含：

- 服务端建议的 `pollAfterMs`；
- 最小和最大轮询间隔；
- 随机抖动，避免大量客户端同时请求；
- 请求失败后的指数退避；
- 页面隐藏时降低轮询频率；
- 网络重新上线后立即唤醒；
- `AbortController` 取消旧请求；
- 内部 token 使已经过期的响应失去提交资格。

即使某个底层请求没有正确响应 abort，token 检查仍然能够阻止旧结果覆盖当前任务。

### 6. 刷新恢复

Vuex 中每次模型训练相关 mutation 后，都会将草稿保存到 `localStorage`，逻辑位于 [trainingDraftStorage.js](../src/domain/training/trainingDraftStorage.js)。

保存内容包括：

- 当前阶段；
- `draftId` 和 `revision`；
- 幂等键；
- `jobId`、状态和版本；
- 任务信息；
- 算法配置；
- 最终结果。

不会保存：

- `File` 对象；
- 完整 CSV rows；
- 内存仓库中的有效数据内容。

这是有意的，因为把完整数据集序列化到 `localStorage` 容易超出容量，并可能阻塞主线程。

因此恢复分两种情况：

- 已经创建远程异步 job：根据 `jobId` 继续查询；
- 还依赖本地 CSV：回退到数据步骤，并提示重新上传。

### 7. 取消语义

点击取消后，前端先进入 `cancelRequested`，再调用取消接口。如果取消接口失败：

- 页面恢复可操作状态；
- 显示取消失败；
- 不会把任务伪装成已经停止。

这里必须区分：

```text
取消前端 HTTP 请求 ≠ 服务端训练已经停止
```

只有服务端返回 `cancelled`，页面才能确认任务真正终止。

### 8. 前后端边界

状态机、幂等键生成、旧响应过滤、轮询调度和草稿恢复属于前端实现；幂等唯一约束、训练任务执行、持久化状态和真正停止计算必须由后端完成。

## 六、纯前端演示如何兼容原项目

项目没有在每个页面到处编写 `if (demo)`，而是在 Axios 客户端中注入 Adapter：

```text
Vue 页面
→ 原有 API 函数
→ Axios 请求层
→ Demo Adapter 或真实 HTTP Adapter
```

业务请求和算法请求分别使用独立客户端，公共请求能力位于 [http.js](../src/utils/http.js)。

默认演示模式下：

- 业务接口延迟约 140 ms；
- 算法接口延迟约 420 ms；
- 推荐和预测根据请求内容生成确定性结果；
- 模型、历史方案和 job 保存在 `localStorage`；
- 训练 job 按时间经过 `queued`、`running`、`finalizing`、`succeeded`；
- 最终 `MAPE 3.84` 明确标记为 Demo 数据。

训练阶段模拟实现在 [demoBackend.js](../src/demo/demoBackend.js)，演示 CSV 位于 [demoDataset.js](../src/demo/demoDataset.js)。

设置以下环境变量后，请求层不再安装 Demo Adapter，页面会继续调用真实业务和算法地址：

```dotenv
VUE_APP_DEMO_MODE=false
```

因此纯前端演示没有破坏真实后端接入路径。

## 七、贯穿四个亮点的请求正确性

页面快速切换机台、模具或数据类型时，多个请求可能乱序返回。

项目使用 latest-only 请求协调器，实现在 [requestCoordinator.js](../src/utils/requestCoordinator.js)：

1. 同一业务 key 发起新请求；
2. 取消该 key 的旧请求；
3. 为新请求保存新的 controller 和 sequence；
4. 请求完成后再次检查它是否仍是最新请求；
5. 如果已经过期，即使成功返回也抛出 stale 错误。

所以这里有两层保护：

```text
AbortController：尽量停止旧请求
结果身份检查：阻止无法取消的旧响应更新页面
```

同时，请求层会把取消、超时、网络错误、HTTP 错误、业务错误和响应结构错误统一转换成 `ApiError`，页面不需要分别处理各种 Axios 错误形态。

## 八、四个亮点之间的关系

| 业务阶段 | 用户问题 | 前端实现 | 用户结果 |
| --- | --- | --- | --- |
| 数据探索 | 字段太多，难定位和比较 | 字段目录、别名归一、纵向投影、选列对比 | 用户直接聚焦目标字段 |
| 数据准备 | CSV 规模和格式不可控 | 分块解析、组合预算、有限预览、取消 | 错误在进入算法前被发现 |
| 参数决策 | 推荐、人工修改和结果混在一起 | 参数 Schema、不可变快照、diff、指纹 | 方案可比较、可回退、可验证 |
| 模型训练 | 长任务刷新丢失、重复提交和状态倒退 | 状态机、幂等键、版本、轮询、草稿 | 任务状态明确且能够恢复 |

四个亮点分别解决不同阶段的问题，没有重复堆砌技术名词：

- 字段目录解决“怎么看数据”；
- CSV 管线解决“数据能否安全进入流程”；
- 方案实验室解决“如何理解和确认推荐”；
- 训练状态机解决“长任务如何可靠执行和恢复”。

## 九、面试时的完整讲法

可以按照下面顺序介绍：

> 项目面向注塑工艺和质量人员，核心流程是生产数据探索、数据导入、参数推荐、人工确认和模型训练。项目中单条机台记录约有 260 个字段，我没有继续使用全宽表，而是建立统一字段目录，将数据组织成摘要、纵向详情和选列对比。参数调优部分基于 76 项 Schema 建立基线、算法推荐、人工稿和预测快照，通过内容指纹判断质量结果是否过期。训练数据入口使用 Papa Parse 分块解析，并用行数、列数和单元格总量共同控制资源。模型训练则使用事件驱动状态机、幂等键、状态版本和退避轮询，处理刷新恢复、重复提交和乱序响应。没有后端时通过 Axios Adapter 提供确定性演示，但算法精度和真实任务执行仍明确属于后端能力。

如果面试官继续追问，可以分别展开：

1. 为什么没有直接使用横向虚拟列表；
2. 为什么参数快照必须不可变；
3. 为什么内容指纹比单独使用 revision 更可靠；
4. 为什么 CSV 需要组合资源预算；
5. 为什么完整 rows 不进入 Vue 响应式状态；
6. 幂等键如何避免创建重复任务；
7. `statusVersion` 如何处理轮询响应乱序；
8. 为什么前端取消请求不等于服务端任务停止。

## 十、真实性结论

| 能力 | 当前结论 | 简历表达边界 |
| --- | --- | --- |
| 高维字段搜索、纵向详情、记录对比 | 已实现并完成页面验证 | 可以写“实现” |
| 参数快照、diff、回退、结果过期 | 已实现并测试 | 可以写“实现” |
| CSV 分块解析、预算、取消、预览 | 已实现并测试 | 可以写“实现”，不能写完整业务规则 |
| 五步训练状态机和草稿恢复 | 已实现并测试 | 可以写“实现” |
| 异步 job 协议 | 前端实现并通过纯前端模式验证 | 应写“设计并验证” |
| 推荐、预测和训练数值 | 纯前端确定性模拟 | 不能当作真实算法精度 |
| 服务端任务持久化和幂等约束 | 需要真实后端 | 只能作为扩展方案讨论 |

当前四个亮点均能形成完整的“问题 → 方案 → 实现 → 用户结果”故事；后续普通样式调整、依赖升级和一般 bug 修复不需要重新修改简历定稿。
