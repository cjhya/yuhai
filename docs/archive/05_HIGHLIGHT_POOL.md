> 使用原则：候选池不等于最终简历亮点清单。A 表示当前已有基础，B/C/D 中未完成的方案不能写成“项目已经实现”。最终仍应只选择 3～5 个真正落地、能够验证和深入讲解的方向。

## 一、分类与评分说明

### 来源分类

| 分类 | 含义 |
| --- | --- |
| A 已有 | 当前源码已存在核心实现，可以直接定位，但仍可能有生产边界 |
| B 可增强 | 当前已有基础能力，经过重构、性能或可靠性增强可形成亮点 |
| C 可新增 | 当前没有完整实现，但从现有业务自然延伸，值得补充最小可运行版本 |
| D 架构扩展 | 业务规模扩大后可能需要，当前主要用于方案讨论，不建议优先开发 |

### 分数解释

- 简历价值、技术深度、面试追问价值、CRUD 区分度：1 分最低，5 分最高。
- 被问穿风险：1 分表示当前已有充分代码和验证；5 分表示当前如果当作已实现写进简历，很容易被源码或追问击穿。
- 成本以一名熟悉项目的开发者为参考。涉及后端、算法服务和部署环境时会显式说明。

## 候选 01

### 亮点名称

浏览器侧 CSV 导入、Excel 导出与 PDF 报告工作流

### 来源

**A 已有。**

### 对应业务问题

工艺人员的数据来源和交付形式仍大量依赖表格，需要把 CSV 试验数据带入参数推荐/模型训练，并把生产数据或模型详情导出为 Excel、PDF。

### 当前实现

- `src/views/ParameterTuning.vue`、`src/components/tab/createModel/model_training/DataSelect.vue` 使用 FileReader 和 Papa Parse 读取 CSV；
- `src/views/dataManage.vue:120-132` 使用 xlsx 导出 Excel；

这些能力已经存在，但文件大小、空文件、列 schema、主线程阻塞和 canvas 释放尚未处理。

### 核心技术原理

浏览器 File/Blob/FileReader、文本编码、CSV 序列化与类型推断、Blob 下载、XLSX 工作簿结构、DOM → canvas → PDF 栅格化过程，以及大对象和 canvas 的内存生命周期。

### 是否需要修改代码

**需要。** 当前能力可以证明“做过文件处理”，但若作为生产亮点，需要补文件边界、错误处理和测试。

### 学习成本

**中。** 需要理解浏览器文件 API、内存占用和第三方格式库，不需要新增复杂框架。

**3/5。**

## 候选 04

### 亮点名称

多服务请求可靠性与高频交互竞态治理

### 来源

**B 可增强。**

### 对应业务问题

业务后端和算法服务返回格式、耗时和失败模式不同；用户快速搜索、切换机台或重复提交时，需要保证只展示最新结果，并在超时、取消、401 和业务失败时可恢复。

### 当前实现

项目有 `request.js`、`requestAlg.js`、修改全局 Axios 的 `api.js` 三套请求入口；地址、timeout 和拦截器不一致。DebouncedSelect 只有 debounce，没有取消/序号控制，且在上一次 options 子集上继续筛选。多个页面缺少 catch/finally，失败后可能永久 Loading。

### 目标方案

用 client factory 生成业务/算法两个独立实例，共享认证、request ID、错误归一化、取消和日志脱敏；页面采用统一 request state。搜索和详情请求实现 AbortController 或 sequence latest-wins；只对满足幂等条件的请求有限重试；稳定字典使用可失效 TTL 缓存和并发 Promise 去重。

### 核心技术原理

Promise 状态、Axios interceptor、AbortController、闭包与请求序号、debounce/throttle、HTTP 幂等性、指数退避与 jitter、缓存 key/TTL/失效、single-flight 和并发 401 协调。

### 是否需要修改代码

**必须。** 当前三套请求层和竞态行为都是源码可见问题。

### 最小实现成本

**3～5 个工作日。** 统一两个实例、错误模型、finally、DebouncedSelect latest-wins 和核心页面迁移。

### 完整实现成本

**2～3 周。** 全页面迁移、缓存、幂等重试、401 协调、契约校验、错误观测和性能验证。

### 学习成本

**中到高。** 需要掌握异步竞态、HTTP 语义和缓存一致性，不能停留在“封装 Axios”。

### 简历价值

**5/5。**

### 技术深度

**5/5。**

### 面试追问价值

**5/5。**

### 和普通 CRUD 项目的区分度

**4/5。**

### 被问穿风险

**5/5。** 当前只能证明简单 Axios 和防抖；若宣称竞态、取消和缓存治理，必须有代码与测试。

### 推荐程度

## 候选 05

### 亮点名称

可恢复、可取消、幂等的算法训练任务中心

### 来源

**B 可增强。** 当前已有同步训练请求和五步 UI，但没有任务模型。

### 对应业务问题

模型训练是长耗时、高成本操作。用户刷新、断网、重复点击或关闭页面后，系统仍需知道后台任务是否运行、能否取消、能否恢复和是否重复创建。

### 当前实现

`src/api/useAlgorithm.js:13-15` 用 GET `/train/{productSeries}/{algorithm}` 同步触发训练；`AlgorithmSelect.vue` 一直等待最终结果。没有 job ID、进度、取消、重试、幂等键和刷新恢复；算法请求没有 timeout。

通过 `POST /training-jobs` 提交任务并携带幂等键，返回 job ID；前端保存 job ID，以带退避和抖动的轮询查询 queued/running/succeeded/failed/cancelled；支持停止前端轮询、后端取消、失败重试、断线恢复和多标签页同步。只有频率和规模证明轮询不足时再升级 SSE/WebSocket。

### 核心技术原理

HTTP 方法语义、幂等键、有限状态机、轮询退避、取消的前后端边界、最终一致性、任务持久化、断线恢复、跨标签通信与重复提交防护。

## 候选 08

### 亮点名称

服务端驱动的数据表格、请求竞态与异步导出

### 来源

**B 可增强。**

### 对应业务问题

模型任务、历史参数和生产数据增长后，全量下载和客户端 filter/sort/slice 会增加网络、内存和计算开销；用户快速换页/筛选还会产生旧响应覆盖，导出全部结果会阻塞浏览器。

### 当前实现

数据管理、TaskManage 和 historyParameter 均请求 `/list` 全量数据后客户端分页；`api/model.js`、`parameterHistory.js` 已有分页接口但页面未使用。用户管理只筛当前后端页，Excel 导出遍历完整 `tableData`。

### 目标方案

建立通用 query model：page/pageSize/sort/filters/search，与 URL 同步；服务端返回 items/total/version；请求 latest-wins，可有限预取相邻页；写操作按 query key 失效。全量导出提交后端任务，前端轮询状态并下载制品。

### 核心技术原理

服务端分页和查询复杂度、URL 状态、请求取消/竞态、分页缓存与失效、虚拟列表适用边界、异步导出任务和最终一致性。

### 是否需要修改代码

**必须，并需后端查询/导出接口配合。**

### 最小实现成本

**2～4 个工作日。** 先在模型任务页使用已有分页接口，完成筛选、换页和 latest-wins。

### 完整实现成本

**2～3 周跨端工作。** 统一三个页面、URL 状态、缓存、异步导出和性能测试。

### 学习成本

**中。** 重点是服务端查询状态、竞态和缓存，不需要过早引入虚拟列表。
